## 4. Skill and Agent Improvement Recommendations

### Skill Improvements

**1. po-agent/SKILL.md — Cross-reference BSA findings before Wave 0 close**
The PO skill should include a step: "Before issuing Wave 0 decisions, check if any BSA output is available from a prior run. If BC-06-class conflicts exist in prior run artifacts, resolve them in Wave 0 rather than leaving for CLARIFICATIONS.md." In run_2, BC-06 was discoverable from run_1 BSA output.

**2. dev-lead-agent/SKILL.md — Resolve "verify input dict shape" before implementation brief**
The Dev Lead skill should mandate: "For any reused function call (calculate_daily, write_report, etc.), read the function signature from source before issuing the implementation brief. Do not leave dict shape questions as open items for code review." This resolves the calculate_daily key names gap in run_2.

**3. backend-dev-agent/SKILL.md — Read referenced function signatures from source**
Same as above applied to Backend Dev: "If your implementation calls an existing function, read its signature from source code. Do not leave input/output shapes as open questions." Backend Dev in run_2 flagged `calculate_daily()` dict keys as uncertain despite the source being available.

**4. backend-qa-agent/SKILL.md — Produce test file skeletons alongside scenarios**
Add to the output types: "Test File Skeletons — empty `def test_<id>_<scenario>():` stubs in the target test files, alongside the BACKEND_QA_SPEC.md. These stubs should be placed in the output directory for direct use by Backend Dev." This bridges the gap between test spec and test code.

**5. qa-lead-agent/SKILL.md — Trigger uat-agent conditionally**
The QA Lead should check: "If the product is in implementation-complete state (all change items have implementation specs), invoke the uat-agent with the UAT handoff note as input." In run_2, the QA Lead produced the UAT handoff note but did not invoke the uat-agent — which would have provided Phase 3 prototype acceptance validation.

**6. sre-agent/SKILL.md — Quantify risk impact before deferral recommendation**
The SRE skill should include: "When recommending a reliability improvement for deferral to a future phase, include a brief impact statement: what is the failure scenario and what would the user experience be? This supports PO prioritisation decisions." The atomic report write deferral in run_2 lacked this context.

### Agent Improvements

**1. loop-operator.md — Detect and resolve overlapping [REVIEW REQUIRED] items early**
The loop operator should run a de-duplication pass on REVIEW REQUIRED items as each wave completes, not only at Wave 3 consolidation. This would allow Wave 2 agents to receive pre-resolved items from Wave 1 rather than re-raising them.

**2. loop-operator.md — Enforce background agent pattern clarity**
The current SKILL.md states agents must be launched as background Agents with `run_in_background: true`. In practice the orchestrator produces agent outputs sequentially in-context. The loop-operator instructions should either: (a) acknowledge the sequential fallback pattern explicitly, or (b) provide a working example of how to spawn a genuine sub-agent in the claude-sonnet-4-6 environment. The gap between the instruction ("launch as background") and the reality (sequential in-context) creates confusion in the audit trail.

**3. All agents — Source file reading before raising open questions**
A cross-cutting improvement: agents should be instructed to "read source files directly when answering questions about existing function signatures, method names, or CSV schema columns before raising a [REVIEW REQUIRED] item." In run_2, approximately 3 open questions (calculate_daily input shape, filter combo attribute names, extend_dialog DateEdit presence) were raiseable as REVIEW REQUIRED but were directly answerable from source files.

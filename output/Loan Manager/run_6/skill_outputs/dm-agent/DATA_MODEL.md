## Schema Evolution Diff (v5 → v6)

### TC-08 Option A (No change)
No schema change. `new_due_date` continues to serve dual purpose:
- For mode != Paidoff: `new_due_date` = post-extension due date
- For mode = Paidoff: `new_due_date` = paidoff_date

**DM Assessment:** Acceptable for prototype scope. Creates a semantic ambiguity documented only in code comments.

### TC-08 Option B (Recommended by DM)
Add `paidoff_date` column to `pending_report_records.csv`:

| Column | Type | Notes |
|---|---|---|
| ... (all existing columns) | ... | Unchanged |
| paidoff_date | ISO 8601 Date / empty | NEW — populated only for mode=Paidoff reports |

**Migration impact:** NONE. Existing pending_report_records.csv files gain an empty `paidoff_date` column on next write. `csv.DictReader` reads missing columns as empty string → parsed as None.

**DM Recommendation: Option B.** The column is cheap to add, the semantic is cleaner, and it prevents future developer confusion about `new_due_date` meaning two different things.

### [REVIEW REQUIRED] TC-08
DM recommends Option B. User confirmation required.

## BC-02 Schema Impact

### Option A (No change to write logic)
No schema change. Values stored as typed by user. Filter comparison uses `.lower()` already.

### Option B (Lowercase normalization)
No schema change. Value format changes: "BG1" written as "bg1". Existing data unaffected (already lowercase in sample data).

### Option C (Title case normalization)
No schema change. Value format changes: "bg1" written as "Bg1". Sample data values change display: b1 → B1, bg1 → Bg1, d1 → D1, dg1 → Dg1.

**DM Recommendation: Option B.** Consistent with sample data. No read-time parsing changes. Filter already case-insensitive — write normalization only affects display aesthetics.

### [REVIEW REQUIRED] BC-02
DM recommends Option B. User confirmation required.
